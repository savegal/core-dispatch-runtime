## 🏗️ Архитектура

### Основные компоненты

#### 1. **MonitoredBlogger** (база данных)
- **Назначение**: Центральная сущность для мониторинга блогера
- **Хранит**: `last_checked_at`, `last_seen_video_id`, `lock_until`
- **Используется**: Воркером для определения, когда проверять блогера

#### 2. **CreatorSource** (база данных)
- **Назначение**: Подписка пользователя на блогера
- **Связь**: `monitored_blogger_id` → `MonitoredBlogger`
- **Настройки**: `mode` (manual/autopilot/notify), `default_template_id`, `interval_minutes`
- **Важно**: Один `MonitoredBlogger` может иметь множество `CreatorSource` (разные пользователи)

#### 3. **CreatorVideo** (база данных)
- **Назначение**: Найденные видео блогеров
- **Статусы**: `new` → `queued` → `done`/`failed`/`skipped`
- **Связь**: `creator_id` → `CreatorSource`, `task_id` → `Task` (опционально)
- **Уникальность**: `(creator_id, video_id)` — одно видео может быть у разных подписок

#### 4. **VideoBatch** (база данных)
- **Назначение**: Хранение списка `video_ids` для преодоления лимита Telegram `callback_data` (64 байта)
- **TTL**: 24 часа
- **Используется**: В уведомлениях и Inbox для передачи списка видео

#### 5. **video_monitor_worker** (сервис)
- **Назначение**: Периодическая проверка блогеров на новые видео
- **Логика**: 
  - Проверяет `MonitoredBlogger` по `interval_minutes`
  - Находит новые видео через TikTok API
  - Создает `CreatorVideo` со статусом `new`
  - Для `autopilot` режима: создает заказы автоматически (с лимитами)

#### 6. **Inbox** (API + UI)
- **Назначение**: Единая точка управления новыми видео
- **API**: `/api/video-inbox/videos`
- **Фильтры**: `new`, `queued`, `done`, `failed`, `skipped`
- **UI**: Главная кнопка "📥 Inbox" в меню парсинга

## 🔄 Поток данных

### Сценарий 1: Новое видео обнаружено

```
1. video_monitor_worker проверяет MonitoredBlogger
   ↓
2. Находит новое видео через TikTok API
   ↓
3. Создает CreatorVideo (status="new", creator_id=...)
   ↓
4. Проверяет режим CreatorSource:
   
   A) mode="manual_review" → Уведомление в бот
      → notify_pending_review(creator, videos)
      → Создает VideoBatch
      → Отправляет уведомление с кнопками
   
   B) mode="autopilot" → Автоматическое создание заказа
      → auto_create_tasks(creator, videos)
      → Проверяет default_template_id
      → Проверяет лимиты (max_videos_per_tick, max_tasks_per_hour)
      → Проверяет баланс
      → Создает Task(ы)
      → Обновляет видео: status="queued", task_id=...
   
   C) mode="notify_only" → Только уведомление (без действий)
```

### Сценарий 2: Работник комментирует через Inbox

```
1. Работник нажимает "📥 Inbox" в меню
   ↓
2. Видит список новых видео (status="new")
   ↓
3. Выбирает действие:
   A) "✅ Комментить все" → Выбор шаблона → Подтверждение → Создание Task
   B) "🎯 Выбрать" → Выбор конкретных видео → Выбор шаблона → Task
   C) "🗑 Пропустить все" → Обновляет статус на "skipped"
   ↓
4. После создания Task:
   - CreatorVideo.status = "queued"
   - CreatorVideo.task_id = task.id
   - Task отправляется в очередь Redis
   ↓
5. Executor обрабатывает Task
   ↓
6. После завершения:
   - Если успешно: CreatorVideo.status = "done"
   - Если ошибка: CreatorVideo.status = "failed"
```

### Сценарий 3: Автокомментирование (autopilot)

```
1. video_monitor_worker находит новые видео для блогера с mode="autopilot"
   ↓
2. Проверяет default_template_id:
   - Если нет → видео остаются status="new" (деградация в Inbox)
   ↓
3. Проверяет лимиты:
   - max_videos_per_tick (например, 10)
   - max_tasks_per_hour (например, 30)
   ↓
4. Проверяет баланс пользователя
   ↓
5. Создает Task(ы) для видео (1 Task на пачку или 1 Task на видео)
   ↓
6. Обновляет видео: status="queued"
   ↓
7. Если лимит/ошибка/нет денег:
   - Видео остаются status="new"
   - (Опционально) Уведомление пользователю
```

## ⚙️ Техническая реализация

### Статусы видео (единый стандарт)

| Статус | Описание | Переход из | Переход в |
|--------|----------|------------|-----------|
| `new` | Найдено воркером, не обработано | - | `queued`, `skipped` |
| `queued` | Заказ создан, Task в очереди | `new` | `done`, `failed` |
| `done` | Задача выполнена успешно | `queued` | - |
| `failed` | Задача завершилась с ошибкой | `queued` | - |
| `skipped` | Вручную пропущено работником | `new` | - |

**Устаревшие статусы** (не используются):
- `pending_review` → заменен на `new`
- `approved` → заменен на `queued`
- `rejected` → заменен на `skipped`

### Режимы блогера (CreatorSource.mode)

| Режим | Описание | Поведение |
|-------|----------|-----------|
| `manual_review` | Ручная проверка | Уведомление → работник решает через Inbox |
| `autopilot` | Автокомментирование | Автоматическое создание заказов (с лимитами) |
| `notify_only` | Только уведомления | Уведомление без действий |

### Лимиты автокомментирования

**Настройки в `config/settings.py`:**

```python
AUTOPILOT_MAX_VIDEOS_PER_TICK: int = 10  # Максимум видео за один цикл проверки
AUTOPILOT_MAX_TASKS_PER_HOUR: int = 30   # Максимум задач в час на блогера
```

**Логика в `services/video_monitor_worker.py`:**

1. Проверка `default_template_id` (обязателен для autopilot)
2. Ограничение количества видео за тик: `videos[:AUTOPILOT_MAX_VIDEOS_PER_TICK]`
3. Проверка лимита задач в час (через счетчик в БД или Redis)
4. Если лимит превышен → видео остаются `status="new"`

### Callback data (Telegram)

**Ограничение**: 64 байта на `callback_data`

**Решение**: Использование `VideoBatch`

```
Старый формат (не работает для >10 видео):
vp:new_videos:select_template:{creator_id}:{video_id1},{video_id2},...,{video_id50}
                                            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                             >64 байта ❌

Новый формат:
vp:new_videos:select_template:{creator_id}:{batch_id}
                                            ^^^^^^^^
                                            ~10 байт ✅
```

### Run-now (принудительная проверка)

**Эндпоинт**: `PATCH /api/video-parsing/creators/{id}/run-now`

**Логика**:
```python
# Сбрасывает MonitoredBlogger (не CreatorSource!)
monitored = MonitoredBlogger.get(creator.monitored_blogger_id)
monitored.last_checked_at = None  # Воркер возьмет в работу
monitored.lock_until = None        # Снимаем блокировку
```

## 🔌 API Endpoints

### Video Parsing

| Метод | Endpoint | Описание |
|-------|----------|----------|
| `GET` | `/api/video-parsing/creators` | Список блогеров пользователя |
| `POST` | `/api/video-parsing/creators` | Создать блогера |
| `PATCH` | `/api/video-parsing/creators/{id}` | Обновить настройки блогера |
| `DELETE` | `/api/video-parsing/creators/{id}` | Удалить блогера |
| `PATCH` | `/api/video-parsing/creators/{id}/run-now` | Принудительная проверка |
| `POST` | `/api/video-parsing/review/{video_id}/approve` | Создать задачу для видео |
| `POST` | `/api/video-parsing/review/{video_id}/reject` | Пропустить видео (status=skipped) |
| `GET` | `/api/video-parsing/review-queue` | Получить новые видео (устаревший, используйте Inbox) |

### Video Inbox

| Метод | Endpoint | Описание |
|-------|----------|----------|
| `GET` | `/api/video-inbox/videos` | Получить видео Inbox (с фильтром по статусу) |
| `POST` | `/api/video-inbox/videos/{video_id}/skip` | Пропустить видео |

### Video Batch

| Метод | Endpoint | Описание |
|-------|----------|----------|
| `POST` | `/api/video-batch/create` | Создать batch (список video_ids) |
| `GET` | `/api/video-batch/{batch_id}` | Получить batch по ID |

```

```

```
1. Открыть карточку блогера

   - Новые видео автоматически получают заказы

```
1. Настроить блогера: режим "👀 Ручная проверка"

### Тест 6: Лимиты автокомментирования

```
1. Настроить блогера: режим "🤖 Авто-комментарий", default_template_id
2. Установить лимит: AUTOPILOT_MAX_VIDEOS_PER_TICK = 5
3. Дождаться когда воркер найдет >5 новых видео
4. ✅ Ожидаемый результат:
   - Созданы заказы только на 5 видео (первые)
   - Остальные видео остались status="new" в Inbox
   - В логах: "Autopilot: max_videos_per_tick limit reached"
```
