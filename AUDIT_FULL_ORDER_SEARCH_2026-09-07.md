# Проверка поиска главных комментариев в полном заказе

Проверены продолжение поиска после ответа, выбор следующего родителя, разбор DOM, прокрутка, проверка автора/ID и исключение обработанных родителей. Подтверждены ошибки реализации, которые объясняют повторные проходы и часть возможных пропусков. Исправления внесены в текущую рабочую копию, поверх предыдущих изменений.

## Что подтверждается логом

В заказе №1098 у попытки `task_1098_parallel_reply_v2_a1_acc1573` общий поиск нашёл 1 из 9 главных комментариев: [executor.log:95539](C:/Users/daboo/Desktop/TeletanSoft/logs/executor.log:95539). Ответ был подтверждён рядом с родителем через DOM, хотя транспорт сообщил пустое тело: [executor.log:95597](C:/Users/daboo/Desktop/TeletanSoft/logs/executor.log:95597). После ответа оставалось 8 родителей и 81,55 секунды поиска: [executor.log:95602](C:/Users/daboo/Desktop/TeletanSoft/logs/executor.log:95602).

Затем вместо продолжения поиска всех оставшихся целей начинались отдельные проходы по одному тексту. В этой части лога присутствуют сбросы `scope_scroll_reset_after_current_viewport_miss`: например, [executor.log:95608](C:/Users/daboo/Desktop/TeletanSoft/logs/executor.log:95608). Это подтверждает механизм возвратов вверх. Сам по себе возврат не означает повторную отправку тому же родителю.

## Найденные ошибки и исправления

| Ошибка реализации | Что изменено |
|---|---|
| Частичная находка прерывала общий поиск, после чего каждый оставшийся текст искался отдельно с возвратом вверх. Пока искался один текст, другие видимые цели могли не обрабатываться. | После обработки найденных родителей оставшиеся цели продолжают искаться вместе с сохранённой позиции. Время отправки по-прежнему не расходует бюджет поиска. |
| На повторном вызове сканер сбрасывал список в начало после промаха в текущем окне. | Добавлен явный режим продолжения без сброса. После прохода до конца сохраняется ограниченный резервный поиск, чтобы проверить также область выше начальной позиции. |
| Срез первых 250 элементов DOM выполнялся до проверки попадания в видимую область. На длинном списке видимый поздний комментарий мог вообще не попасть в разбор. | Ограничение применяется после отбора элементов текущего окна списка. Проверено на комментарии №280 из 320 загруженных строк. |
| Наличие хотя бы одной строки стандартной разметки исключало другие варианты разметки из списка кандидатов. | Стандартные и запасные селекторы рассматриваются совместно. |
| Общая обёртка нескольких родителей могла считаться одним комментарием и скрывать последующие строки. Первый скрытый текст или имя автора также могли мешать извлечению нужного текста. | Групповые обёртки не поглощают отдельные строки; выбирается подходящий видимый текст. Проверено, что вложенные ответы и повторные обёртки одного родителя не становятся дополнительными родителями. |
| Родителю без ID мог присваиваться ID вложенного ответа. | ID извлекается из элемента родителя или обёртки его текста, без произвольного выбора первого ID внутри ветки ответов. |
| После прокрутки пустая или ещё не обновившаяся строка могла быть пролистана до завершения подгрузки. | Подозрительное окно перечитывается один раз после короткого ожидания, в пределах прежнего бюджета. Проверена отложенная отрисовка строки. |
| При уточнении ID через общий кэш локальная переменная обновлялась, но в очереди мог оставаться старый объект. Пропущенные по защите от дублей элементы также могли оставаться в очереди текущей попытки. | Обновляется сам элемент очереди; уже обработанные и заблокированные родители исключаются из текущего прохода. Это не помечает неудачную отправку успешной. |

В лог добавлены `reply_parent_search_continued_after_partial`, `viewport_hydration_retry` и ограниченные по количеству сообщения `text_match_rejected`. Последние показывают несовпадение автора или ID у совпавшего текста. Проверка автора, различение одинаковых текстов у разных родителей, вложенность ответов и правила подтверждения отправки сохранены. Отсутствие тела ответа TikTok по-прежнему само по себе не отменяет успех, подтверждённый в DOM.
