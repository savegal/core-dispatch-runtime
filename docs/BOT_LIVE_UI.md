# Карточки заказов и живой интерфейс Telegram

Обновление от 06.11.2026. Это оформление существующего Telegram-бота: используются его обычные сообщения и кнопки. Права доступа, HTTP-публикации, расчёты и алгоритм лайков этим изменением не меняются.

## Что видит пользователь

- Главное меню TeletanSoft объясняет три основные точки входа: создание, текущие заказы, шаблоны.
- В мастере отдельно показаны библиотека текстов, количество главных на видео и число ответов под каждым публично подтверждённым главным. У ответов тоже отдельная библиотека вариантов.
- Предварительная карточка показывает итог на видео и на весь заказ, пул, стоимость, лимиты и краткие примеры текстов. План при конверсии 10–18% прямо называется оценкой; это не обещание фактического результата.
- Живая карточка начинается со статуса и этапа. Полоса отражает число видео с подтверждённой целью, а не число обработанных видео. Завершение обработки с ошибками не даёт заполненную полосу.
- Главные и ответы имеют отдельные блоки: публично подтверждено, HTTP-отправки, принятые CID, ожидание проверки, неопределённый исход, ошибки и попытки без отправки.
- Последние события показывают фактическое время и состояние, короткий текст. Время среза и последнего события берётся из ответа API и явно обозначено UTC.
- У публикации с настоящим CID есть кликабельная ссылка «Открыть комментарий» или «Открыть ответ»; у ответа отдельно доступен «Родитель». Ссылки показаны в живой ленте и во всех страницах раздела «Публикации». Превью сайтов отключено, чтобы карточка оставалась компактной.
- Ссылки используют формат TikTok из предоставленной выгрузки: `/share/video/<media_id>?cid=<base64url CID>`. Старые записи без отдельного media ID используют ID из сохранённой ссылки на видео/фотопост. При неизвестном CID или неизвестном ролике ссылка на комментарий не выдумывается. Доступность публикации для других аккаунтов остаётся отдельным статусом.
- Если последнее чтение видит меньше публикаций, чем подтверждалось ранее, карточка показывает оба числа. Историческая отметка не выдаётся за доказательство текущей видимости.
- Вкладка конверсии показывает результаты по каждому тексту с пагинацией. TXT, CSV и ссылки остаются отдельными действиями.

Карточка запрашивает данные примерно каждые три секунды, пока заказ или проверка активны. Анимации и произвольного роста процентов нет. Кнопка «Обновить» позволяет получить свежий срез вручную. После пяти ошибок загрузки карточка сохраняет последний известный результат и явно пишет, что автообновление приостановлено. То же уведомление появляется после истечения часа просмотра. Переход на другую вкладку отменяет подписку до изменения сообщения.

Неподтверждённая отправка не называется доказанной модерацией. Полученный CID и публичная видимость описаны раздельно. Ошибка/остановка не скрываются за надписью о завершении; ожидающие поздние проверки остаются видны.

## Проверка оформления

HTML и пользовательские тексты экранируются до отправки. Превью длинных библиотек ограничены без разрыва HTML-элементов и сущностей. Новые тесты проверяют лимит Telegram в UTF-16, инъекции HTML, крайние размеры библиотек, отсутствие ложных 100%, корректное время, завершённые/остановленные состояния и изменение только клавиатуры. Результаты сетевой проверки TikTok описаны отдельно в `BACKEND_TIKTOK_AUDIT.md`; тесты интерфейса не подтверждают боевую конверсию.

Финальный объединённый прогон backend/UI/ссылок/шаблонов: **198 passed**, 52,07 с. Ссылки дополнительно проверены декодированием точного CID, привязкой к родителю, пагинацией всех ответов и отсутствием активной ссылки при неизвестном CID. Нажатие ссылок в реальном мобильном приложении Telegram/TikTok не проверялось; прямой GET пользовательского примера сохранил CID после перенаправления и вернул HTTP 200.

## Файлы этого оформления

- `bot/services/order_presentation.py` — общие числа, время, шкала, ограничение и экранирование текста, главное меню.
- `bot/services/live_orders.py` — живые карточки, статистика текстов, обновление и уведомление о его приостановке.
- `bot/handlers/quantity_orders.py` — мастер и предварительная карточка заказа/шаблона.
- `bot/handlers/orders.py` — названия вкладок и ручное обновление.
- `bot/handlers/templates.py` — связь количества публикаций и независимой библиотеки текстов.
- `bot/handlers/menu.py` — единое главное меню во всех точках входа.
- `tests/unit/test_live_order_presentation.py` — сценарии достоверности и размеров сообщений.
- `services/publication_links.py`, `services/publication_reports.py`, `tests/unit/test_publication_links.py` — единый безопасный формат ссылок, ссылки ответа/родителя в отчётах и регрессии.
- `docs/BOT_LIVE_UI.md` — это описание.

Реальные сообщения пользователям в ходе проверки оформления не отправлялись. Для использования интерфейса нужен процесс бота с обновлённым кодом.
