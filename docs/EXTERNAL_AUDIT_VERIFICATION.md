# Проверка внешнего аудита HTTP-контура

Проверено по текущему коду 6 ноября 2026 года. Вложенный текст использован как список гипотез; его рекомендации не применялись автоматически. Старые изменения проекта сохранены.

## Что подтвердилось и что изменено

| Пункт аудита | Вердикт и итог |
|---|---|
| 1.1. `{}` обязательно означает WAF-отказ | Не доказано. После отправленного POST пустой JSON, отсутствие подписи в наблюдаемом URL или последующий переход на login не доказывают, что сервер не сохранил действие. Сохраняется неопределённый исход без слепого повторения. Отдельно исправлено ложное завершение legacy-результата `submitted_unconfirmed` без настоящей квитанции. |
| 1.2. Синтетические session aliases повышают рейтинг guard-only cookies | Подтвердилось для стандартного hex `sid_guard`, в отличие от прежних тестов с произвольными строками. Оценка качества и структурная валидация теперь читают явный состав cookies через `restore_guard_aliases=False`. Guard больше не становится сильной сессией из-за парсинга. Совместимое восстановление для браузера сохранено. |
| 1.3. Символ SDK появляется раньше готовности подписи | Подтвердился риск раннего разрешения POST. Непосредственно HTTP-клиент и quantity-publisher требуют свидетельство подписанного запроса текущего документа. Одного `sdk_present` недостаточно. Слабое SDK-свидетельство осталось допустимым для начального GET-прогрева, иначе получилась бы циклическая зависимость. |
| 1.3. Нужно переносить `x-secsdk-*` из шаблонов заголовков | Не подтверждено. Ограничение заголовков намеренное: браузер управляет UA/cookies, SDK может сформировать свои security headers в перехватчике fetch. Передавать старое значение SDK-заголовка из шаблона не следует. Сохранены application-owned `accept`, `tt-csrf-token`, `content-type`; Chromium-тест проверяет работу SDK-перехватчика и генерацию им заголовка. |
| 1.3. Публикация без page отправляется через request context | Подтвердилось. POST публикации без живой страницы теперь возвращает `not_sent` / `publish_requires_live_page` до сетевого вызова, включая случаи с переданными готовыми параметрами подписи. Request context остаётся доступным для чтения. |
| 1.4. API timeout съедает бюджет SSR | Подтвердилось, включая зависшее тело ответа после успешных HTTP-заголовков. У API отдельный AbortController и бюджет до половины общего времени, не более 2500 мс; SSR получает оставшееся время и не использует уже отменённый API-сигнал. Ограничены и fetch, и чтение тела ответа. |
| 1.4. Chrome 120 по умолчанию при импорте | Подтвердилось в двух местах. Новые значения по умолчанию берутся из `desktop_user_agent()`. Явно предоставленные пользователем UA и старые существующие профили массово не переписываются. |
| 2.1. Заказ прекращается после первого inconclusive | Подтвердилось. Принятые слоты получают до трёх дополнительных чтений с паузами 2/5/10 с без нового POST. Это работает и после исчерпания лимита отправок: проверка уже отправленного действия не является новой отправкой. Время, трафик и стоп-сигнал по-прежнему ограничивают работу. После исчерпания проверок результат остаётся неполным, а не успешным. |
| 2.2. Два частичных читателя считаются достаточными для всех CID | Подтвердилось. Для каждого ещё не найденного CID нужны два полных независимых чтения; положительный результат одного подходящего наблюдателя достаточен. Лимит подбора читателей сохранён. Формулировка «навсегда» из аудита преувеличена: фоновые поздние проверки существовали и раньше. |
| 2.3. Пустая библиотека ответов вызывает modulo by zero | Подтвердилось. Новый helper учитывает `replies`, `reply_variants` и legacy-поля `reply1`…`reply20`, не наследуя старое ограничение `reply_count=3`. Пустая библиотека даёт понятную ошибку до публикации; `ensure_actions` также защищён самостоятельно. |
| 2.4. Keyword checkpoint оставляет одну квитанцию | Подтвердилось. Checkpoint сохраняет все результаты durable-целей и объединяет их с уже записанными квитанциями. Сохраняются дополнительные поля результата, media ID и warnings. Конкретный пример возврата денег «15 → 1» из текста не воспроизводился; потеря входных данных леджера устранена, а сама тарифная формула не менялась. |
| 2.4. Keyword-исполнитель преждевременно закрывает общий pool | Подтвердилось как нарушение владения ресурсом. Pool остаётся у executor до проверок и следующих URL. Внутренняя keyword-функция не закрывает его даже при отмене; окончательный shutdown выполняет владелец executor. Индивидуальные страницы и leases продолжают освобождаться своими helpers. |
| 3.1. Неполный SQL-батч обрывает обход reply-пула | Подтвердилось. Продолжение и выбор резервных кандидатов теперь зависят от курсора исходного списка ID, а не от длины фактически полученных строк. Тест исключает одну строку из первого батча после построения ID-списка и находит подходящий аккаунт во втором. |
| 3.2. Cookies всех кандидатов повторно разбираются | Подтвердилось. Классификация кешируется по SHA-256 фактического содержимого, с ограничением 4096 записей. Cookies в кеше не сохраняются. Полная SQL-проекция ID/cookies для глобальной сортировки остаётся: это позволяет находить горячие аккаунты за первой страницей. Это оптимизация повторного JSON-разбора, а не заявление об устранении всех чтений O(N). |
| 3.2. Импорт повторяет полную предзагрузку на каждой пачке | Подтвердилось. Одна работа импорта использует общий private index. Перед повторным использованием проверяется его согласованность: SQLite — версия данных других соединений плюс счётчик записей accounts на переиспользованном соединении; PostgreSQL — хеш набора ID/xmin. Изменения и повторная авторизация инвалидируют индекс. Изменения схемы БД не требуются. |
| 3.3. Session обязательно держит connection всё время await | Сама по себе открытая Session этого не означает. Но rollback/ленивая загрузка ORM действительно могли открыть транзакцию перед браузерным ожиданием. Нужные поля загружаются до последнего commit; транзакции закрываются перед сетевыми этапами. Селектор, захват бюджета и основные commits quantity-action выполняются в worker thread с ожиданием незавершённой операции при отмене. Поздно выбранный аккаунт освобождается, слот до POST возвращается в `not_sent`. Для release используются сохранённые ID/тип действия без новой ленивой SQL-загрузки после commit. Полной миграции всего ORM-контура на AsyncSession не выполнялось; короткие SQL-операции остаются синхронными. |
| 3.3. Windows `future.result()` блокирует FastAPI | Подтвердилось в трёх местах. Все три вызова используют ожидаемую асинхронно worker-операцию с таймаутом. Контекстный ThreadPoolExecutor, который дополнительно ожидал shutdown после timeout, удалён из этих маршрутов. |
| 4.1. Проверку domain нужно инвертировать | Сам диагноз неточен: и `tiktok.com`, и `.tiktok.com` допустимы. Навигация не исправляет невалидный payload `add_cookies`. Удалён бесполезный прогрев с повтором тех же cookies; ошибка возвращается без вывода значений cookies. |
| 4.2. Ранний возврат страницы теряет proxy usage lease | Подтвердилось. Возврат и закрытие страницы освобождают lease в finally, включая чужой/уже потерянный context и исключение драйвера без close-события. |
| 4.3. Закрытие остановленного заказа ждёт lock зависшего acquisition | Подтвердился риск. Незавершённые acquisition принадлежат заказу и отменяются перед закрытием его страниц. Закрытие уже известной страницы может прервать её RPC, не ожидая занятого account lock. Реестр контекста остаётся под контролем его владельца. |

## Как проверено

Новые регрессии находятся в `tests/unit/test_external_audit_fixes.py`. Они проверяют реальные hex guard-cookies, SQL-пагинацию с потерянной строкой, повторное чтение без повторного POST и при исчерпанном dispatch budget, legacy-тексты, сохранение нескольких keyword-квитанций, частичные наблюдения разных веток, отсутствие открытой транзакции перед браузерным I/O, отзыв acquisition при занятом lock, освобождение proxy lease, неблокирующую Windows-валидацию и согласованность импортного индекса после повторной авторизации.

В Chromium используются настоящие fetch, cookies и HTTP-сервер на localhost. Тесты отдельно проверяют SSR после зависшего тела API, неопределённый `{}` без повтора POST, границу SDK-symbol / signed dispatch и сохранение browser/SDK ownership заголовков. Для транспортных фикстур готовность подписывающего окружения задаётся отдельным завершённым локальным GET; тесты самой готовности используют непрогретую страницу.

Общий unit-прогон: **3077 passed**, 13 предупреждений, 528,29 с. Общий Chromium-прогон: **55 passed**, 282,59 с. После последнего усиления SQL-отмены и cleanup дополнительно прошёл набор **72 passed** (18 новых регрессий плюс guards/recovery/quantity); отдельно прошли **4 passed** сквозных main/reply сценария в Chromium. После окончательного ограничения обеих фаз mentions дополнительно прошли **2 passed** настоящих браузерных сценария зависшего тела API и SSR. `compileall`, Ruff `F821/F823` и `git diff --check` прошли.

Промежуточные наборы также проходили: 157 профильных проверок; 94 проверки леджера/денег/количества/восстановления; 31 проверка новых регрессий/импорта/cookie pipeline. Наборы пересекаются и не складываются. Полный unit-прогон не повторялся после последних локальных изменений SQL-отмены: они покрыты указанными 72 проверками и сквозными сценариями.

Новые тесты изолированы от реальных аккаунтов, Redis и TikTok; публикации на площадке в рамках этой проверки не выполнялись. PostgreSQL-ветка согласованности индекса написана для его стандартных системных версий строк, но не проверялась на живом PostgreSQL; текущие DB-тесты используют SQLite. Не заявляется подтверждение текущей боевой конверсии или прохождение CAPTCHA.
